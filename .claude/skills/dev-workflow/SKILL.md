# 开发流程

分支、验证关卡、提交授权、十三条纪律和隐私规则以仓库根目录的 `AGENTS.md` 为准，
本文只列出按顺序执行的步骤。需求见 `docs/requirements.md`，架构见
`docs/architecture.md`，操作和配置示例见 `docs/usage.md`。

## 开始任务

1. 检查分支与工作树：新任务建功能分支，继续任务沿用已有分支并保留未提交修改。
2. 读取相关实现、调用点、schema 与测试，确认真实需求和边界。
3. 找到已有单一真相，例如 `ConfigSchema`、`isUsable`、`credentialFingerprint`，
   复用而不是复制（纪律 #4）。

## 实现

1. 改代码或文档；从用户入口确认功能接通（纪律 #9）。
2. 关卡性质的改动写完即变异，确认断言失败后恢复（纪律 #1/#2）。
3. 测试驳回时先判断契约、实现和断言哪方错误（纪律 #3）。
4. 同步 `docs/requirements.md`、`docs/architecture.md`、`docs/usage.md` 和相关 skill，
   删掉过期说明（纪律 #7）。

## 验证与合入

1. 运行 `npm run validate`；`tests/integration/service.test.ts` 依赖构建产物，
   不能用局部测试代替完整关卡。
2. 检查 diff 与敏感文件结果。
3. 按用户授权本地提交，记录改动原因、测试范围、变异结果和剩余限制。
4. 需要合入且已获授权时再申请 MR；未通过验证不得申请。
