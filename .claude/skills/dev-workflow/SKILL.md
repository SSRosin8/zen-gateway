# zen-gateway 开发流程

本项目**不用 worktree、直接在 main 上提交**（私人自用工具，单人开发）。
不用 worktree：它解决的是多人并行改同一仓库的隔离问题，单人单分支下只增加一层目录切换成本。

真正硬性的是下面这些，每一条都对应一个真实发生过的缺陷。

## 写代码前

**读相关代码再动手。** 本项目的注释密度偏高是刻意的：很多约束的理由来自
实测，写在注释里。动一处之前先读那处的注释 —— 它常常已经解释了
"为什么不能按看起来更自然的方式写"。

**查一遍是不是已经有单一真相了。** 纪律 #4：守卫/名单/判定必须从唯一真相
推导。已经踩过四次：路由与鉴权名单分叉、`GROUP_TYPES` 两份手写副本、
`isUsable` 被手写第二份、`credentialFingerprint` 一处用 sha256 一处用长度。

判断标准：**"这件事的答案有没有第二处也在回答？"** 有就抽出来，
而不是让两份"今天恰好一致"。

## 写完立刻变异它

**"写了断言"不等于"关卡成立"。** 要问**这条断言的失败路径是否真的可达**，
并真的改坏实现跑一遍。

变异存活时**先分四类**，不要直接补测试：

| 分类 | 处置 |
|---|---|
| 测的路径不存在 | 改测试，让它真的走到那条路径 |
| 条件被另一层顺带满足 | 改测试，构造只有这一层能挡的输入 |
| 输入集为空 | 改 fixture |
| **代码里有死信息** | **改代码**，不是补测试 |

第四类最容易搞错。第十轮的例子：`best.id !== activeBridgeId` 恒为 true
（走到那里意味着当前内核不在 usable 里，而 best 取自 usable），
改成恒 true 没有任何断言会红 —— 那不是缺测试，是那行本身该简化。

**变异本身也要确认打中了目标。** 一个没打中的变异会伪装成"测试是空壳"，
方向刚好相反。改完先 grep 确认落点。

## 性质不可观测时，退一步守实现选择

有些性质在行为上**根本测不到**。实测：`secureCompare` 换成
`return actual === expected` 对所有输入给出完全相同的布尔值，
差别只在耗时，而 JS 里的耗时测量被 GC/JIT/分支预测的噪声完全盖过 ——
拿时钟写断言只会得到一条随机会红的测试，**比没有更糟**。

这时的做法是：守住**产生该性质的实现选择**（源码级断言
「必须委托给 `timingSafeEqual`」），并在注释里**写明这是源码级而不是
行为级**。假装覆盖到了才是真正的危害。同一手法也用在
「不再用 `disabled:opacity-*` 表达禁用态」上。

## 测试红了先判断是代码错还是断言错

已出现十余次，**代码错与断言错各约一半**。所以既不能默认"代码错"
（会改坏对的代码），也不能默认"断言错"（会把缺陷钉成预期行为）。

Phase 10 的例子：导入订阅节点时 schema 报
`该代理只能经 Clash 桥接，但 clash.enabled 为 false` —— 那是**代码错**
（订阅里绝大多数节点只能桥接，不处理会造出存不下去的配置），
而不是 schema 太严。

## 报告前必须真跑

**文档里声称的能力，要像跑测试一样真跑一遍**（纪律 #7）。
到第六轮为止这类错误出现了十余次，形态高度一致：

- 把"代码里有这个能力"写成"用户能看到它"
- 配置示例自己违反同一份文档解释的校验
- 数字凭记忆写（**会漂的数字本就不该写进文档**）
- 诊断手段只在一半路径可用
- 两份文档对同一实测结论说法相反

**「实现了 + 有测试」不等于「接上了」**（纪律 #9）：一个功能的验收必须是
端到端看到它的输出。Phase 9 发现出口隔离视图**结构上永远无法成立** ——
`applyProbeResult()` 零生产调用点，而七轮审核都没查到，因为每一层单独看
都是对的。

## 提交

```bash
npm run validate   # typecheck(三份 tsconfig) + 双构建 + 全部测试
```

`build` 必须排在 `test` 之前 —— `service.test.ts` 要 spawn
`dist/server/index.js`，而 `dist/` 是 gitignored 的。

- git user 在**本仓库局部**配置（`ssrosin8`），**不动全局**
- 绝不提交：`data/`、`opencode.json`、`.env*`、真实 key
- 提交信息写清**为什么改**与**变异验证结果**；末尾带 Co-Authored-By
- 数字（测试数、行数）只写在提交信息里，**不写进文档**

## 不要做的事

- **不要为了行数拆文件。** 本项目从未有过行数硬上限。
  `relay.ts` 801 行，实测仍只有一个调用者 —— 决定不拆，直到出现真实的
  第二调用者。判据是**当下可测的调用点数量**，不是对未来的推断（纪律 #11）。
- **不要给没有生产读者的成员补测试**假装它被用着。手写的
  "有没有读者"标注必然漂（实测一轮内漂了两处）—— 唯一真相是调用点本身。
- **不要在 doctor 里重新实现任何判定逻辑。** 它是诊断工具，
  必须与产品共享同一份判断（纪律 #8/#4）。
